# Poke Royale - 자동 진행 링 축소 서바이벌 (GitHub Pages + Firebase)

배팅/코인 기능이 없는 서바이벌 추첨 미니게임입니다. 관리자가 버튼을 누를 필요 없이 일정에 따라 자동으로 진행됩니다.

## 규칙

- 배틀은 **2시간마다, 한국 시간 홀수 시 30분**에 열립니다. (01:30, 03:30, 05:30 ... 23:30)
- 다음 배틀 시각 전까지 누구나 닉네임을 입력하고 **[참가하기]**를 누르면 새 캐릭터가 생성되어 참가자에 추가됩니다.
  - 한 사람(브라우저)당 회차마다 1개, 같은 회차에 같은 닉네임은 불가, 참가 후 취소 불가
  - 한 회차 최대 30명 (먼저 참가한 순). 인원이 많을수록 캐릭터가 자동으로 작아집니다.
- 배틀 시각에 참가자가 **6명 이상**이면 10초 카운트다운 후 배틀이 시작되고, 최후의 1인이 우승합니다.
- **6명 미만**이면 배틀 없이 취소되고 다음 회차(2시간 뒤)를 기다립니다. 참가 신청은 회차마다 새로 받습니다.
- 모든 회차 결과(우승자, 참가 인원, 취소 여부)는 **명예의 전당**에 영구 저장됩니다. [우승 순위] 탭에서 닉네임별 우승 횟수를 볼 수 있습니다.

## 공정성과 자동 진행의 원리

- 배틀 시각이 되면 참가자 명단이 확정됩니다. 참가 시각은 Firebase 서버가 기록하므로 마감 후에는 아무도 끼어들 수 없습니다.
- 확정된 명단으로 시드를 만들고, **모든 브라우저가 똑같은 배틀을 각자 계산**해서 동시에 재생합니다.
  - 아무도 접속해 있지 않아도 배틀은 일어나고, 나중에 들어온 사람도 같은 장면과 같은 우승자를 봅니다.
  - 특정 브라우저가 결과를 조작할 수 없습니다. 저장된 기록이 계산 결과와 다르면 화면에 "검증 필요"가 표시되고, 관리자가 접속하면 자동으로 바로잡힙니다.
- 페이지가 열릴 때마다 기준 배틀을 한 번 계산해 브라우저가 정확히 계산하는지 스스로 검사합니다.

## 파일 구성

```
index.html             화면, 참가, 배틀 계산과 재생, 명예의 전당, 관리자 기능 전부
database.rules.json    Firebase 보안 규칙 (참가 마감 시각 검증, 기록 위조 방지)
runners/               runner1.png, runner2.png ... 를 넣는 곳 (없으면 기본 마커 표시)
```

캐릭터 번호는 그 회차 참가 순서입니다. `runners/runner3.png` 를 넣으면 매 회차 3번째 참가자의 캐릭터가 그 이미지로 표시됩니다.

## 1. Firebase 준비 (처음 한 번)

1. https://console.firebase.google.com 에서 프로젝트를 만듭니다.
2. **Realtime Database** > 데이터베이스 만들기 > "잠금 모드로 시작"
3. **Authentication** > 로그인 방법에서 **익명**(참가자용)과 **이메일/비밀번호**(관리자용)를 사용 설정합니다.
4. **Authentication > 사용자** 에서 관리자 계정(이메일 + 비밀번호)을 하나 만듭니다.
5. **Realtime Database > 규칙** 에 `database.rules.json` 내용을 붙여 넣고, `ADMIN_EMAIL_HERE` 를 관리자 이메일로 바꾼 뒤 [게시]합니다.
6. **프로젝트 설정 > 내 앱** 에서 웹 앱을 추가하고, `firebaseConfig` 값을 `index.html` 상단 `FIREBASE_CONFIG` 에 옮겨 적습니다.
   `databaseURL` 이 없으면 Realtime Database 화면 상단 주소를 넣으세요.
7. `index.html` 상단 `ADMIN_EMAIL` 에도 관리자 이메일을 적습니다.
8. **Authentication > 설정 > 승인된 도메인** 에 `아이디.github.io` 를 추가합니다.

## 2. GitHub Pages 업로드

1. 새 저장소(Public)를 만들고 이 폴더의 파일을 저장소 최상단에 업로드합니다.
2. Settings > Pages > Branch: main / (root) > Save
3. 1~2분 뒤 `https://아이디.github.io/저장소이름/` 으로 접속합니다.

이전 버전(수동 시작 방식)을 이미 올렸다면 `index.html` 과 `database.rules.json` 을 교체하고, Firebase 규칙도 새 내용으로 다시 게시하세요.
이전 버전이 남긴 `room`, `match` 데이터는 Firebase 콘솔에서 지워도 됩니다.

## 3. 관리자 기능

관리자 패널에서 비밀번호로 로그인하면:

- **참가 제외**: 다음 회차 참가자 중 부정 참가자를 뺍니다. (마감 전까지)
- **전체 기록 다시 계산**: 저장된 모든 참가 기록으로 결과를 다시 계산해 명예의 전당을 검증하고 틀린 기록을 바로잡습니다.

관리자 계정은 참가할 수 없습니다. 관리자도 참가하려면 다른 브라우저나 시크릿 창을 쓰세요.

## 일정이나 인원 바꾸기

`index.html` 상단에서 바꿀 수 있습니다.

| 항목 | 위치 | 기본값 |
| --- | --- | --- |
| 배틀 간격 | `SCHEDULE.INTERVAL_MS` | 7200000 (2시간) |
| 기준 분 | `SCHEDULE.OFFSET_MS` | 1800000 (30분, 한국 시간 홀수 시) |
| 최소 인원 | `GAME.MIN_PLAYERS` | 6 |
| 최대 인원 | `GAME.MAX_PLAYERS` | 30 |
| 결과 화면 유지 | `GAME.RESULT_HOLD_MS` | 60000 (1분) |

**간격이나 기준 분을 바꾸면 `database.rules.json` 의 숫자 7200000 과 1800000 도 똑같이 바꿔서 다시 게시해야 합니다.**
(예: 짝수 시 30분으로 바꾸려면 OFFSET 을 5400000 으로, 규칙의 1800000 도 5400000 으로)

## 알아 둘 점

- 참가자 구분은 브라우저 단위입니다. 다른 기기나 시크릿 창으로 여러 캐릭터를 만드는 것은 기술적으로 막을 수 없으니, 같은 닉네임 패턴의 중복 참가는 관리자가 [참가 제외]로 정리하세요.
- Firebase 무료(Spark) 플랜은 동시 접속 100명까지입니다.
- 결과가 각 브라우저에서 계산되므로, 개발자 도구를 다룰 줄 아는 사람은 배틀 시작 직후 결과를 미리 알 수 있습니다. 다만 이미 명단이 확정된 뒤라 결과를 바꿀 수는 없습니다.

## 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| "Firebase 설정이 필요합니다" 창 | `FIREBASE_CONFIG` 를 채웠는지 |
| 참가하기를 눌러도 실패 | 마감 직전인지, 같은 회차에 같은 닉네임이 있는지, 규칙을 게시했는지 |
| 로그인 방식이 꺼져 있다는 오류 | Authentication 에서 익명 / 이메일 로그인 사용 설정 |
| 관리자 기능에서 "권한이 없습니다" | 규칙의 `ADMIN_EMAIL_HERE` 를 바꿨는지 |
| 승인되지 않은 도메인 오류 | Authentication > 설정 > 승인된 도메인에 github.io 주소 추가 |
